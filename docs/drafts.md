# 草稿备份与恢复

正文通过 [共同编辑](collaboration.md) 同步，标题通过属性接口独立保存；个人检查点保存版本说明、上传任务及本机恢复副本。自动备份不修改正式版本或当前标题，只有保存版本成功才追加 revision。

AI snapshot 取得编辑锁，执行直接更新草稿；普通 read 不加锁。旧代次无未确认输入时跟随最新状态，有未确认输入或来源不明时导出并保留 recoveryOnly 副本，不自动补交。完整 editEpoch 规则见 [Agent 文档](agent-editing.md#旧页面和离线输入)。

## 保存时机

| 变化/事件 | 行为 |
| --- | --- |
| 正文、标题、说明、图片位置 | 约 500ms 写 IndexedDB，连续输入最长约 1.5s；本地事务完成后才算已备份 |
| 原始共同编辑事件 | 约 16ms 合批，服务端正文/名单/收据同事务确认；旧协议保留 1–5s 兜底 |
| 个人说明或图片任务 | 约 30s 补存完整服务端检查点；首次上传和保存版本前提前同步 |
| 本机存储失败 | 显示警告，检查点同步缩短到 5s；网络重试退避最长 120s，联网恢复后重试 |
| visibilitychange/pagehide | 尽力补存，不保证异常退出前最后一笔未完成写入 |

正文变化不单独触发周期整篇 JSON 请求。未上传图片可先备份，但不能保存正式版本或显示“完整草稿已同步”。

正文快照使用浅引用并整体替换，调用方不得原地修改。输入只推进修改代次并标记待核对，空闲约 200ms 核对指纹；连续输入仍由最长 1.5s 的备份期限收束，切页、保存、恢复等边界即时核对。撤销回基线在核对后恢复一致状态，不在逐键同步 watcher 中克隆/序列化全文。同一代次的不可变快照可共用，进行中的异步写入保留捕获时的旧快照。

入口为 `app/utils/draft-storage.ts`、`draft-sync.ts`、`app/composables/use-requirement-draft.ts`。IndexedDB 初始读写探测及后续失败分别处理；业务校验未通过的说明仍允许本机备份。兼容检查点中的 title 字段继续保留，但协作页面恢复时不把旧标题写回当前文档；未提交的标题输入由标题控件保留，失败可重试或取消。

## 身份与恢复

- 本机按账号/需求隔离；服务端只返回本人的草稿，管理员也不能读取他人个人检查点。
- 页面先恢复本机与服务端记录再编辑：本机有未同步内容时优先本机，否则用服务端；沿用原草稿 ID，不制造恢复副本，不按天数自动过期。
- 完整 Yjs 与 collaborationEdits 原事件队列一并备份；响应丢失或离线重开按原 ID/顺序补交，缺旧事件时标记修改人未记录。离线参与者记入确认时版本，不补写旧 revision。
- 即使正文撤销回基线，未确认队列仍需保存。保存版本前等待原事件确认，期间新内容须接续备份成功再清理旧副本。
- 结束草稿保留不含正文/标题/说明的墓碑，拒绝迟到写入；只清理与最后同步内容一致的本机副本。保存响应丢失后继续输入，新增内容仍可恢复。
- 未知或损坏格式不自动删。旧记录图片 src 为空等错误不证明当前正文损坏；合法记录继续恢复，异常记录及原事件保留。

## 离开或切换需求

`useRequirementDraft` 同时保护 onBeforeRouteLeave 和 onBeforeRouteUpdate。页面实例固定需求 ID，不能因新路由参数把旧正文写到另一需求。

切换前等待正在进行的标题属性保存，以及正文、说明、Yjs、原事件、图片任务与 Blob 的完整本地事务。等待期间有变化则重新备份；仅队列变化也不能跳过。结果明确区分无需备份、本机完成、服务端确认和阻止离开。

已完成及进行中的同代检查点可以复用。令牌覆盖页面修改、Y.Doc/原事件队列、草稿身份、个人确认编号、恢复归档状态和 editEpoch；读取令牌前先收束事件记录器。只有事务成功后才记录完成，失败仍重试，等待期间代次变化仍补写。完整 Yjs 编码只在 Y.Doc 更新后失效，不能从 JSON 重建历史来生成检查点。

本机不可用时，只有编辑事件已确认、个人检查点已同步且不存在仅在本机的未完成图片，才可离开。两条路径都无法完整保存时留在原页提示重试。正式保存和导航互斥，重复/取消导航不提前释放其他进行中的锁。

Header 搜索、最近浏览、其他路由及前进后退复用此保护。当前页完整备份失败仍阻止离开；目标详情的读取失败在跳转后的详情页处理，查询文字保留。选择在新标签页打开时不离开原页，新详情恢复成功才记访问。返回沿用原事件/上传 ID，并恢复标签页阅读位置；清空浏览历史不影响草稿。见 [快速切换](requirement-quick-switch.md)。

## 接口与保存

| 接口 | 语义 |
| --- | --- |
| `GET /api/requirements/:id/drafts` | 本人的 drafts 和 closedIds，禁止缓存 |
| `PUT /api/requirements/:id/drafts/:draftId` | mutationId + 完整 snapshot，成功递增编号；expectedVersion 不限制保存 |
| `DELETE /api/requirements/:id/drafts/:draftId` | 幂等结束本人草稿；expectedVersion 不限制结束 |

snapshot 含 baseRevisionId、title、contentJson、changeNote、pendingUploads。标题可暂空，上限 240 字符；说明 500 字符，请求 4 MiB，图片任务最多 100 个，记录任务/块 ID、文件信息、位置与顺序。

服务端校验唯一 diffId、拒绝 blob: 正文地址，不静默改快照或按旧编号拒绝保存。客户端串行同步，响应丢失原 ID/快照重试，确认后再发后续内容；键顺序不算差异，数组顺序及 ID 仍参与。结束草稿的写入返回 410，客户端自动接续未提交内容。

正式保存带 draftId、clientSaveId、collaborationUpdate 及代次，先合并共同状态并校验本人和上传任务，再在行锁内追加版本、结束检查点。clientSaveId 按作者唯一，重试不重复建版；保存中的新共同输入继续保留。

保存期间禁用本人的正文、标题和说明输入。提交在本地校验通过后立即收起版本弹窗，随后提交待保存标题、准备草稿并写入版本，Toast 跟随请求。取消或失败保留说明及草稿，响应不明时重试沿用冻结的原请求与 `clientSaveId`，不能替换成新内容。成功只清除该次提交的说明；等待或重试期间的新正文与新说明接续备份。写入成功但列表刷新或本地收尾失败时明确说明已保存，不提示重新建版。同步、个人备份、正式版本分开显示；属性更新不能重新初始化正文，切换比较保留编辑器和图片任务。

保存前等待的协作编辑请求也有 15 秒超时。当前 ofetch 1.x 在传入 `signal` 后不会执行 `timeout`，因此协作请求显式合并页面取消与超时信号；单次超时不能取消整个页面的控制器。超时后保留原编辑事件和说明，结束保存提示，并允许恢复网络后重试。

KeepAlive 停用不能跳过离页守卫：仍须等待本地完整事务或可确认的服务端副本，双重失败留在当前页。停用时释放 navigationPending，移除周期同步定时器；本地备份及未完成上传的恢复资料继续保留。重新激活重新启用同步；LRU 淘汰时走正常卸载、补存并关闭存储连接，之后从检查点恢复。隐藏状态下上传回调不得强行插入只读正文，保留原任务供恢复编辑后重试。

## 图片与清理

1. 新图片立即分配任务及图片块 ID。Blob 在 IndexedDB 独立表保存，正文/位置同事务；普通输入不重复写图片字节。
2. 首次上传前建立服务端草稿，携带 draftId/uploadId；按用户/任务去重，并写 requirement_draft_assets。
3. 已上传但响应丢失可凭原任务 ID 领取结果，仍校验本人、需求和有效草稿；恢复时重用原文件和 ID。
4. 成功后按映射位置插入正式节点，已有同块不重复插入；blob: 预览不是持久化依据。
5. 服务端确认完整快照且本机无更新后才删已完成任务的本地文件；未上传 Blob 保留，换设备缺文件须提示。

草稿引用保护到草稿结束，移出正文的近期上传仍可能被保护。结束时解除关联并重置 assets.unreferencedAt，旧资源回退 createdAt，默认再留 7 天。引用写入用共享事务咨询锁，GC 用独占锁；全部保护源见 [资源生命周期](architecture.md#图片与资源生命周期)。
