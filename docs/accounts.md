# 账号与成员管理

角色设置、审批、用户资料/启停/强制退出、凭证和邀请撤销在校验通过后固定目标与输入、立即关闭确认弹窗，使用同一条 Toast 报告结果；失败从页面恢复入口继续，列表刷新失败不视为写入失败。切换账号清除旧反馈。一次性密码、凭证、邀请创建保留原结果界面，复制提示不暴露明文；本人改密、登录和注册保持原表单反馈。见 [通用交互规则](bing-ui.md#本项目用法)。

系统只有固定项目。账号启用状态、加入资格和项目角色分别管理；待审批不等于停用，拥有职业角色也不代表已实现子任务权限。

## 使用入口

| 入口 | 行为 |
| --- | --- |
| 登录页“注册账号” | 创建普通账号及待审批申请；可在个人账号页补充说明、查看原因或重新申请 |
| 超级管理员“系统管理” | 分页搜索账号、处理申请/邀请、修改身份与角色、停用恢复及强制退出 |
| “新增用户”→直接创建 | 设置初始密码，立即加入项目，不经审批、不切换管理员会话 |
| “新增用户”→邀请加入 | 生成 7 天定向链接，由同事注册或登录匹配邮箱后接受，无需再次审批 |
| 项目管理员“成员管理” | 搜索已有成员，调整普通业务角色 |
| 用户菜单“个人账号/修改密码” | 查看本人资格；以当前密码改密，保留本设备、撤销其他会话 |

当前不提供邮件发送、邮箱验证或自助找回密码。初始管理员及紧急重设使用 [交互式改密工具](development.md#首次启动)，它不创建账号、成员关系或恢复停用账号。

登录页采用响应式品牌区与表单布局，沿用静态猫咪 Logo；桌面以 HTML/CSS 预览共同编辑、版本对比和 AI 标注处理，登录中暂停预览，成功时同步显示“已完成”。保留原认证接口与 redirect 行为。校验、可访问性、减少动态效果、场景维护及验证入口见 [登录页交互与视觉](login-experience.md)。

登录和登出在导航确认时同步提交账号状态与目标页面。正常退出期间不会先清空首页身份、收起侧栏或重新请求首页数据；进入工作台的首帧按已保存的侧栏偏好直接排版，手动开合动画继续保留。路由守卫仍在导航前核验最新权限，取消的导航不把候选身份写入全局；退出成功但导航失败/取消时清除本地身份。

个人账号页（REQ-53）沿用工作台的全宽卡片布局：灰色底、实色面板、12px 圆角和浅边线，页面边距及卡片间距均为 12px（≤760px 为 8px）。页面标题保留给辅助技术，不额外占一行，也不再提供页内定位按钮。已加入账号在宽屏并排展示个人资料与账号安全；内容区达到 980px 时，下排 AI 引导与凭证管理作为两张独立卡片并排、顶部对齐，各自按内容决定高度，不撑满剩余屏幕或强制等高。凭证表格通过公开的 `maxHeight` 随视口限制高度，较多记录在表格内滚动，分页保留在滚动区外。顶部个人资料合并姓名、用户名、邮箱、系统身份与项目角色；64px 头像使用账号的 `avatarColor`，与文档负责人保持同色。用户名、邮箱支持鼠标悬停或键盘聚焦后复制，触屏常显按钮。已加入账号不再重复展示工作台入口或“可访问项目”。小屏按可用宽度恢复纵向布局，保留自然滚动，不裁切内容或强行缩小字号。

未加入项目时显示“已注册 → 等待审批 → 已加入”的进度卡，被拒绝时突出显示管理员回复。申请说明、重新申请、手动刷新及邀请提示保持原规则。前台每 60 秒静默检查资格，后台不发起轮询；慢请求不重叠，也不覆盖用户尚未提交的说明。通过后提示并跳转工作台，卸载时取消请求及定时器；状态读取失败只在审批分区提供重试。

账号安全区以一行展示密码说明及修改入口，并预留尚未开放的登录设备行。修改密码弹窗给出仅供建议的强度提示，实时检查两次输入；准入仍为 6–128 字符，始终保留当前会话、撤销其他会话。设备查询、凭证最近使用及个人改名属于后续功能，本期不新增相应接口或数据字段。

仅 `canAccessProject` 为真时挂载 AI 协作及请求凭证。引导依次为创建有效凭证、复制安装说明、在 Codex 中调用 Skill；前两步根据凭证接口与复制成功自动更新。网页不能观测本机 Codex 调用，第三步由“我已完成调用”显式确认。复制与调用的完成标记以版本 1 保存在本站 localStorage 的 `rb-agent-onboarding:<账号 ID>`，不含凭证，账号切换不复用他人的进度；存储不可用时仅保留当前页并提示。三步完成自动收起，键盘焦点移到可展开的说明入口；失去全部有效凭证后重新展开。安装、更新、卸载说明及下载链接始终可见，复制按钮反馈 2 秒。

凭证默认显示有效项，状态标签显示完整总数，只有总数超过一页时才显示分页与条数选择；≤640px 改为卡片并保留分页操作。全部有效凭证参与 7 天内到期提醒，日期旁显示按响应 `asOf` 向上取整的剩余天数；前台空闲每 60 秒刷新，弹窗操作期间暂停。首次读取显示骨架，读取失败只影响凭证区并可重试，已有成功结果保留。分页及计数规则详见 [Agent 凭证](agent-editing.md#安装边界)。

密码、凭证表单与成功结果使用480×480弹窗，视口不足时收缩，中间内容可滚动。创建凭证提供 7/30/90 天及自定义，默认 30 天；数量上限与 1–90 天范围不变。创建成功保留结果界面和“只显示一次”提示，复制按钮位于凭证右侧，复制失败仍可选中明文手动复制；关闭或卸载立即清除明文，重新打开只显示空表单。写入成功后的列表刷新失败不误报为创建失败。撤销确认显示凭证名称及 AI 将立即失去访问权限的说明。

## 身份与权限

系统身份为 `users.role` 的 admin/user，界面显示超级管理员/普通用户。项目角色存在 `project_member_roles`，同一人可多选：

| 标识 | 角色 |
| --- | --- |
| project_admin | 项目管理员 |
| product | 产品经理 |
| developer | 开发 |
| qa | 测试 |
| designer | UI 设计 |
| ops | 运维 |

启用项目成员即使没有职业角色，也可读写文档。超级管理员管理账号、审批、邀请、系统身份和项目管理员资格；项目管理员只能调整既有成员的普通角色。正文与现有状态动作不额外按职业角色或负责人限制，未来设计见 [子任务计划](accounts-and-workflow-plan.md)。

停用优先于角色和成员关系。待审批账号不能读取文档、版本、图片或成员列表；已批准后若成员关系被移除，不能凭旧申请恢复访问。每次请求读取数据库当前权限，管理员也须有有效会话且受固定项目资源范围约束。

## 管理规则

- 用户名为 3–30 位字母、数字、下划线或点，用户名/邮箱规范为小写。密码 6–128 字符，不 trim；规则由 `shared/auth/account-input.ts`、`password-policy.ts` 共享。
- 直接创建默认普通用户，项目角色可为空。密码仅在当前弹窗内存保留供一次性交付，关闭即清除，不写浏览器存储、服务端响应或审计。
- 用户名或邮箱冲突返回 409，不覆盖旧账号。创建用户、credential、成员、角色、撤销同邮箱旧邀请及 user.create 审计同事务提交，不产生申请。
- 停用需原因，撤销全部会话并保留成员关系、角色及历史作者；恢复和系统身份变化后须重新登录。任何管理请求不得停用或降级最后一名启用超级管理员。
- 批准申请至少选一个项目角色，拒绝需非空原因；前后端使用同一校验，失败不改变待审批状态。待审批可改说明，被拒绝可重申，重复批准不重复授权。
- 同项目同邮箱至多一份待接受邀请；重新邀请使旧链接失效。已有成员的角色独立调整，不通过旧邀请追加权限；停用账号须先恢复。

页面使用共享表单规则，失败保留输入；弹窗 footer 通过表单 ID 提交，保留 Enter 与校验。账号、申请、邀请使用服务端分页，默认 20 条、可选 10/20/50/100，筛选回第一页。用户详情显示最近 30 条账号审计。

### 再次复制邀请

等待接受的邀请可经专用接口再次获取原链接，不改变凭证、角色或到期时间。已接受、撤销、过期或邀请者失去权限时拒绝获取；浏览器复制失败时提供手动复制。

旧随机凭证只存摘要，无法还原时返回 `{ url: null }`，页面提示明确重新邀请；取消不改变原记录。不得为了“复制”静默轮换链接。

## 申请操作记录

`project_access_requests` 每人每项目一条当前记录，历史独立在 audit_events，日志条数不代表申请数量。

| 动作 | 含义 |
| --- | --- |
| request.submit | 首次申请；source=registration 表示注册自动申请 |
| request.update | 待审批时修改说明，保存 previousMessage/message，含清空 |
| request.resubmit | 已处理后重申，保留此前状态与审批说明 |
| request.approve / request.reject | 审批结果 |

相同说明不追加日志。旧 request.submit 按已有 source/previousStatus 解释，不猜测缺失的旧值，不改写历史。解释与文案入口为 `shared/auth/audit.ts`、`app/utils/account-audit.ts`。

## 公共审计写入

账号服务和注册钩子共用 `writeAudit(tx, event)`，业务与日志同事务；事件类型、扩展方式和需求属性历史统一见 [操作日志](audit-log-plan.md#公共审计写入)。

## 安全与实现

- Better Auth 管理登录与 credential。注册后建立申请，补建失败仍无项目访问权；管理员直接创建用受控 credential issuer/hashPassword，不调用会自动登录的公开注册接口。
- 账号写事务使用 PostgreSQL advisory lock；锁后重读操作者与会话，串行检查最后一名管理员、审批和邀请消费。重复接受/审批不重复写成员或审计。
- 原生 `/api/auth/admin/**` 返回 404；认证路由允许列表和业务输入白名单防止绕过应用规则。Cookie 写入校验 Origin。
- 本地回环开发的认证来源由 Nuxt 实际监听端口生成，并按 worktree/端口隔离 Cookie；Better Auth、业务写请求与协作 WebSocket 共用配置。生产与自定义域名继续使用显式来源，见 [多 worktree 本地开发](development.md#多-worktree-本地开发)。
- 邀请以 `BETTER_AUTH_SECRET`、项目 ID、邀请 ID 和用途/版本前缀经 HMAC-SHA256 派生 32 字节凭证；数据库只存 SHA-256 摘要，恢复链接时重新派生核对。
- 原链接仅从创建或专用管理员接口返回，Cache-Control: no-store；凭证在 URL fragment 中，页面取出后清除，并暂存当前标签页以支持登录跳转。列表、日志不含凭证；invitation.link.read 只记录取链接，不声称复制成功。
- 同环境实例共用 secret。轮换后旧原链接仍可校验摘要，但不能重新派生，需明确重新邀请；不延长旧邀请有效期。
- 接受邀请核对邮箱、状态、有效期及邀请者当前权限。人工批准或邀请不自动设置 emailVerified。
- 注册/登录按 IP 限流；申请每用户每分钟 5 次，邀请接受 15 次，预览每 IP 每分钟 30 次。不把数据库异常或凭证 SQL 参数透传客户端。

## API

| 方法与路径 | 权限 / 用途 |
| --- | --- |
| `GET /api/account/access` | 登录账号；本人资料（含 `avatarColor`）、申请与资格 |
| `POST /api/account/request` | 登录账号；提交或补充本人申请 |
| `POST /api/invitations/preview` | 持有邀请凭证；预览 |
| `POST /api/invitations/accept` | 登录账号；接受匹配本人邮箱的邀请 |
| `GET/POST /api/admin/users` | 超级管理员；列表 / 直接创建 |
| `GET/PATCH /api/admin/users/:id` | 超级管理员；详情与审计 / 修改资料和角色 |
| `POST /api/admin/users/:id/status`、`POST /api/admin/users/:id/revoke-sessions` | 超级管理员；停用恢复 / 强制退出 |
| `GET /api/admin/requests`、`POST /api/admin/requests/:id/review` | 超级管理员；申请列表 / 审批 |
| `GET/POST /api/admin/invitations` | 超级管理员；列表 / 创建 |
| `POST /api/admin/invitations/:id/link`、`POST /api/admin/invitations/:id/revoke` | 超级管理员；获取链接 / 撤销 |
| `GET /api/members`、`PUT /api/members/:id/roles` | 超级管理员或项目管理员；成员 / 按权限改角色 |
| `POST /api/auth/change-password` | 本人改密，界面要求撤销其他设备会话 |
| `GET/POST /api/account/agent-tokens` | 当前项目可访问账号；本人凭证分页 / 创建 |

分页参数在 `server/utils/account-input.ts`，DTO 在 `shared/auth/access.ts`；最大每页 100 条。邀请链接接口返回 `{ url: string | null }`；不存在/跨项目 404，失效/邀请者失权 410，并在账号事务锁内复核权限。

AI 凭证分页、有效数量和状态规则见 [Agent 凭证](agent-editing.md#安装配置和凭证)。相关回归为 `tests/auth`、`tests/api/accounts.cases.ts`、`tests/api/agent-token-pages.cases.ts` 和 `tests/types/audit.ts`；命令见 [验证矩阵](development.md#按改动选择验证)。
