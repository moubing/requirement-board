# bing-ui 接入约定

本项目从 npm 使用 `@moubing/bing-ui`，当前精确依赖 0.19.0，与文档站和 AI 导出一致。组件 API 和示例由 `bing-ui-docs` 维护；本文只说明查阅方式、联动修改流程和本项目用法。历史升级记录见 [0.18.2 联动验证](bing-ui-0.18.2-validation.md)，后续版本见下方升级回归。

## 本机仓库配置（UI 开发前必做）

首次复制 [dev-repos.example.json](../dev-repos.example.json) 为 `dev-repos.local.json`，填写 `bingUi`、`bingUiDocs` 后执行：

```powershell
Copy-Item dev-repos.example.json dev-repos.local.json
# 填写本机两个源码仓库的路径后检查
pnpm ui:check
```

路径可为绝对路径，或相对本仓库根目录的路径；Windows JSON 使用 `/` 或转义的 `\\`。两项均必填，不能填写 npm 产物或网站地址。本地配置不提交，应用运行、部署和普通 CI 仍只依赖 npm 包。

`BROWSER_TEST_UI_CANDIDATE=1` 联调时，组件入口和 Nuxt 自动导入排除规则共用校验后的实际仓库路径；仅将该仓库的 `dist/` 排除，目录名不必为 `bing-ui`，支持自定义目录和 worktree。

涉及 UI、组件库或文档前必须检查。配置、项目身份或文档入口无效时，停止相关工作并提示补齐；不得猜测同级目录、自动切换仓库或静默回退。

## 按安装版本读取文档

1. 核对本项目 `package.json`、锁文件和已安装包的实际版本。
2. 在配置的 `bingUiDocs` 下读取 `public/llms.txt`、`public/ai/manifest.json`。
3. 确认 `packageVersion` 与安装版本一致、目标组件 `status=verified`，再读取索引指定的组件 Markdown；其中包含可运行示例，无需启动文档站。
4. 版本不匹配时停止按该文档接入并报告差异。已授权的升级任务可继续同步文档，期间用包类型和配置的源码核对 API。
5. 同步后重新核对版本和验证状态；不得修改 `node_modules`，生成导出文件也不等于行为已验证。

## 组件库修改与文档同步

组件库缺陷先记录版本和最小复现。用户将 `bing-ui` 纳入范围后，在配置的源码仓库修复，不在本项目添加组件内部行为的兼容层。

修改组件库时，同一任务必须同步 `bing-ui-docs`：

1. 检查两个仓库的 Git 状态和规则；更新受影响的正文、API、网页预览与独立示例。内部修复也须核对说明和示例。
2. 获得发版授权并发布后，精确升级文档项目依赖，更新 `shared/docs/migration.ts` 的版本与验证状态；文档同步本身不授权发布、推送或部署。
3. 在文档项目运行 `pnpm docs:export`、`pnpm docs:check`、相关类型检查和示例无头验证，不手改 AI 导出产物。
4. 更新本项目依赖和锁文件，运行 `pnpm ui:check --check-versions`，再按 [验证矩阵](development.md#按改动选择验证) 检查受影响交互。

用户明确要求安装刚发布的自有组件版本时，将该精确版本合并到 `pnpm-workspace.yaml` 已有的 `minimumReleaseAgeExclude` 包名规则；pnpm 只使用同一包的第一条匹配，不能追加同名第二条，也不扩大为任意版本豁免。

交付说明须覆盖组件库、文档项目和本应用。无法完成同步或验证时明确说明缺项。

## 本项目用法

| 场景 | 约定 |
| --- | --- |
| 表单 | `BingForm/BingFormItem` 配合共享 Zod 规则；`prop` 对应字段路径，`required` 只是标记；提交检查 `payload.valid` 并使用解析结果 |
| 校验与失败恢复 | 保留默认 `auto` 及提交校验；失败保留输入，重开弹窗或切换审批模式时清理不适用的错误 |
| 弹窗提交 | 使用 footer；表单外按钮用 `useId()` 生成 ID，借 `html-type="submit"`、`form` 提交原表单，保留 Enter 行为 |
| 操作反馈 | 校验通过并固定目标/输入后立即收起确认弹窗；`useOperationFeedback` 用同一 ID 的顶部居中 Toast 更新处理中、成功或失败；失败从原入口恢复输入 |
| 固定弹窗 | `height/maxHeight/maxWidth` 约束框架；设置分类放 `header-addon`，正文滚动不带走头尾；密码/凭证结果复用同一480×480框架 |
| 宽度调整 | BingSplitPane 的 sideSize 保存偏好，resize/end 的 size 为实际值；只在 update:sideSize 提交 Cookie，容器压缩不落盘；BingSlider 与数值框共用归一化设置 |
| 导航 | 路由用 NuxtLink，侧栏通过 custom 插槽接入 BingButton 并保留链接角色和当前页标记；不嵌套交互元素。同页标签用 BingTabs，内容生命周期由业务管理 |
| 表格 | 文档与账号均用真实 total 的 remotePagination；文档另开 remoteSort，分页只由 page-change 请求，筛选/排序/条数改变回第一页；分组共用独立列设置 |
| Header 搜索 | BingAutocomplete（lg）常驻桌面 Header，窄屏收为图标入口；接收业务候选，`openOnEmpty=false`；匹配、导航和最近浏览见 [快速切换](requirement-quick-switch.md) |
| 中文输入 | 组词确认后更新查询，不在 compositionupdate 中写回 model 或手动筛选 |
| 连续差异导航 | 显式关闭 BingButton 点击节流，使每次点击立即响应 |
| 主题 | 根节点 `data-bing-theme` 与语义变量；浮层继承主题，不全局覆盖组件内部样式 |
| 滚动 | 页面及自建滚动区用 BingScrollbar；已有内置滚动区不重复包装，横向须显式启用 `horizontal` |

自定义滚动 viewport 必须把 `viewportRef` 和全部 `viewportAttrs` 绑定到同一个真实滚动 DOM。`vertical=false` 不禁止原生纵向滚动。启用方向固定预留轨道空间，居中页面用公开变量 `--bing-scrollbar-gutter-left` 对称占位，避免轨道显隐挤动内容。

侧栏普通导航与正文/比较切换通过 `afterNextPaint` 先给输入反馈一次绘制机会，再挂载重内容；连续选择只执行最新任务，卸载取消。减少动态效果或隐藏页面直接执行，后台切换与 100ms 兜底避免 rAF 停止后悬挂。修饰键/中键打开链接仍在原事件内执行。这是业务渲染调度，不延迟组件库的 `click` / `update:modelValue` 事件，也不等待碎屑动画播完。

操作提示跟随请求与账号，页面卸载不丢失结果；处理中不自动消失，用户关闭后不复活，退出/切换账号清除旧提示。写入成功即报告成功，后续读取失败改为“操作已成功，最新列表暂未加载”，不引导重复提交。失败不自动弹回抢焦点。

负责人和优先级使用字段级串行合并队列，保持下拉可连续操作；旧响应仅确认本次字段，失败保留最新选择并可重试/取消。状态流转只限制同一状态操作。属性请求不锁住标题、正文、其他属性、Header 搜索和最近浏览；真正离页仍受草稿完整备份和正式保存守卫保护。

版本保存、文档创建、窄屏属性、添加关联、另存模板、角色/审批/用户管理和撤销遵循立即收起规则。模板管理保存留在编辑器。创建文档仅在原创建上下文未改变时跳转，否则保留结果链接。一次性密码/凭证/邀请创建保留专用结果界面；登录、注册、本人改密保留原表单。自动同步、后台加载、普通搜索不弹操作提示，主动复制、刷新和提交提供明确反馈。

## 升级回归

0.19.0 为 Autocomplete 增加 `optionActionLabel` 和独立 `option-action` 事件/内容插槽。Header 搜索在每条结果右侧显示新标签页按钮，结果本身及输入框 Enter 继续当前页导航；不在只读候选内容中嵌套按钮，不设置全局勾选模式。带行尾按钮的浮层使用 grid/row/gridcell 语义；F2 可进入当前按钮，支持上下键、返回输入和关闭。`search` 无头场景使用 npm 正式包，覆盖慢详情/元数据先进入详情页、单次详情读取、失败重试、缓存与草稿保留、鼠标/键盘另开当前或其他文档、SSR 水合及320/390/1440px亮暗布局。

同版将共享点击碎屑改为浏览器原生 transform/opacity 动画，保留轨迹、时长、减少动态效果及清理规则；首帧提交后无需主线程逐帧更新。悬停波纹重置直接清理内联样式，避免大量控件禁用或卸载时反复强制布局。Button、Tabs 及共享反馈仍在原事件内同步通知；侧栏与正文/比较切换通过上述业务调度先绘制输入反馈，Header 搜索直接发起导航，均不等待碎屑动画播完。组件库、文档正文/API、繁忙页面及独立示例、AI 导出与本项目精确依赖同步到 0.19.0。

0.18.4 将 Slider 的竖向样式限定在滑块自身，修复 Dialog 内的纵向 Scrollbar 误触发横向滑块的竖向轨道、位置和气泡样式。设置弹窗继续使用公开的 Slider 属性与事件，不增加内部样式覆盖。实时预览的业务网格同步约束为可收缩列，正文按可用宽度换行，宽表格仍在自己的滚动区横向滚动，避免撑宽弹窗并裁掉右侧预览。组件库正文、API、网页弹窗示例、独立示例及 AI 导出同步升级；验证复用现有设置与字体无头场景，并临时核对 320/390/768/960/1440px 亮暗布局、预览末尾、两条滑块拖动与恢复。

0.18.3 修复 DropDown 的原生 DOMRect 锚点在对象展开时丢失 width/height，导致 `bottom-end` / `top-end` 横坐标及侧向 end 纵坐标失效的问题。工作台继续使用公开 `placement="bottom-end"`，菜单优先在三个点按钮下方右对齐，按钮常驻显示。无需业务层补偿位置。组件库、文档正文/API/网页与独立示例及 AI 导出同步升级；工作台无头回归同时检查普通/减少动效的真实点击、横纵坐标和常驻可见性。

0.18.2 包含 Slider、Input、Textarea 和 Table 的本轮升级，以及 Table 全文提示和外层可聚焦滚动容器的点击修复：

- 设置数字输入接受 `number | null`；空值恢复业务默认值，合法范围由业务判断，失焦 / Enter 的规整由 BingInput 负责。正文和辅助面板滑块分别用 `resetValue=880/360`，与恢复按钮共用默认值和 Cookie 持久化入口。
- 文档标题、代码块名称、手动字体输入使用 `enter` 事件处理提交，保留取消、失焦和防重复请求；文本回调对 null 归一为空字符串。邀请表单已有显隐按钮，显式关闭内置 `passwordToggle`；其他密码框复用内置按钮。
- 短标注通过 `submitOn="enter"` 和 `resize` 接入，Shift+Enter 换行，组词确认不保存。锚定原文的紧凑浮层关闭 `autosizeTransition`，避免高度过渡结束时移动命中区域；表单级快捷键隔离保留，Dialog 已处理的 Tab 首尾循环不再重复执行。
- 选区历史通过 `activeRowKey / row-activate` 切换当前版本，并用 `--bing-table-row-active-accent` 设置标记颜色。凭证首次加载失败使用 `error / retry`，后续刷新失败保留旧列表并显示业务错误提示。
- 7 处表格沿用默认键盘导航；F2 / Enter 进入控件，Esc 返回单元格，普通内容激活与批量选择分开。未接入没有后端全量操作支持的跨页批量全选。没有依赖拍平序号的函数 rowKey 或需要保留的 Table 内部留白覆盖。
- Button 默认不参与 flex 收缩；已有输入侧的 `min-width: 0`、操作按钮的固定宽度继续生效。主题使用公开变量，避免覆盖 `--_table-*` 内部状态。

0.17.0 完善 BingSelect / BingTreeSelect 的字符定位、拼音匹配与高亮、标签折叠和批量操作反馈。Select 的全选入口进入面板头部，并显示三态和当前范围计数；触发器使用 `combobox` 角色，浏览器测试应按该角色定位选择器，普通按钮仍使用 `button`。看板继续通过公开属性和事件接入，不增加内部 DOM 或动效补丁。TreeSelect 的交互冻结与底部占位方案已回退，面板仍按内容自然收缩。相关验证见 [0.17.0 联动验证](bing-ui-0.17.0-validation.md)。

按改动覆盖表单空值、成功与失败恢复、SSR 直接访问、浮层、中文输入、亮暗主题和窄屏。类型正确不能代替运行验证。

历史上出现过控件 ID 重复、Checkbox 聚焦滚动及 SSR Teleport 水合问题，均已有修复；维护相应行为测试即可。Cursor 升级尤其要检查正文段落 DOM 稳定、剪贴板和撤销；0.9.2 的编辑区标记问题由 0.9.3 修正，测量与剩余问题见 [性能评估](editor-scroll-performance-assessment.md)。

0.9.4 修正 Tabs 外层不对称留白导致的可见标签上偏。正文/版本比较与编号、保存按钮继续使用父容器垂直居中；组件内部上下各保留 4px，横向溢出时总高度不变。

0.10.0 为 BingTextarea 默认开启平滑光标，AI 标注输入框直接复用组件能力，保留 Shift+Enter 换行、自动高度、中文组词与输入区滚动；输入值即时更新。无需业务层绘制光标，减少动态效果等场景由组件回退到原生光标。升级验证需覆盖模态输入锁下的真实打字和跨行光标位移。

0.11.1 改善全局 Cursor 的停用快路径及长编辑区样式失效，编辑/只读状态都保护正文节点；公开 API 不变。看板仍使用发布包，候选联调与发布包回归、REQ-8 原图三轮测量及剩余限制见 [REQ-10 验证记录](req-10-performance-validation.md)。

0.11.2 修正 Chromium 页面缩放后普通鼠标被误判为触控板而跳过惯性的问题；继续使用 BingScrollbar 默认配置，不在业务层接管滚轮。`smooth-scroll` 无头场景覆盖正文、版本比较及返回缓存详情后的惯性，详见 [浏览器验证](development.md#需求切换的浏览器验证)。

0.12.x 改为纯 ESM 多文件产物，Shiki、Day.js、dnd-kit 与 `gsap/*` 子路径改为外置依赖，由打包器和 Nitro 追踪；zod 变为可选 peer，本项目已直接依赖。不要使用 0.12.0：其 `dayjs/plugin/customParseFormat` 外置路径缺少扩展名，Nuxt SSR 导入即报 `ERR_MODULE_NOT_FOUND`，0.12.1 已修正。组件内图标类名由 `lucide lucide-*` 改为 `bing-svg-icon bing-svg-icon--*`，业务样式和测试不得依赖组件内部图标类名。本项目未使用新增的 `BingConfigProvider`，尺寸、浮层层级和动效保持组件默认；后续引入时须在根节点统一配置，不逐个页面覆盖。升级回归需覆盖生产构建产物在 Node 中直接加载、登录页 SSR 及工作区、文档、分页/统计和 smooth-scroll 无头场景。

0.12.2 修正 BingSplitPane 在 KeepAlive 缓存期间把 0 宽当作容器变窄的问题：此前文档 A → B → A 返回时，属性栏先以 0 宽渲染一帧，正文宽度从 1190 跳到 830。现在返回的第一帧就是最终宽度。应用侧阅读位置恢复与阅读锚点的协调（见 [编辑器与比较](editor-and-diff.md)）不依赖这项修正，继续保留。0.12.3 修正 BingSelect / BingTreeSelect 打开后在随后两帧内把已移出组件的焦点抢回搜索框的问题；本项目各处选择器的用法无需调整。发布前联调可设 `BROWSER_TEST_UI_CANDIDATE=1`，让 `quick-switch` 浏览器测试加载 bing-ui 仓库本地构建的 `dist/index.js`。

0.12.4 修正可选 Zod 依赖仍被公共声明引用的问题，`BingFormSchema` 仅要求 `safeParseAsync` 校验接口，本项目现有 Zod 规则继续兼容。共享 Tooltip 的打开、切换和关闭按对应触发器读取局部 `reducedMotion`，不再被首个实例影响。已同步同版本的文档正文、API、示例及 AI 导出；应用继续使用发布包，无需增加业务兼容代码。

0.12.5 修复 BingResizable 锁定宽高比时角手柄跨过横纵位移分界的尺寸突跳：指针位移连续投影到起始比例线上，角手柄吸附轴按起始长边保持稳定。看板继续沿用图片节点的比例锁定与尺寸更新方式；编辑器无头回归覆盖四种比例、三种对齐、普通/Yjs 协作模式及重新加载，边手柄、键盘、图片预览和题注交互保持原有行为。

0.13.0 新增 BingDragDrop、BingDraggable、BingDropZone、BingDragOverlay 与 useBingDragDrop 跨区域拖放（只按指针落点判定、触屏长按开始、Escape 取消、可按条目限制落点，不提供键盘拖动，应用须另给菜单入口），以及 BingToast 的单个 `action` 按钮（至少显示 6 秒，异步处理中暂停计时，Promise 失败保留提示供重试）。两项供 REQ-26 个人工作台使用，现有页面尚未接入；已有 Toast 的计时与关闭行为不变。升级回归覆盖类型检查、操作反馈与外壳无头场景、生产构建在 Node 中直接加载及登录页 SSR。

0.13.1 修复 BingDragOverlay 归位动画结束时的交接：dnd-kit 先同步撤掉浮层定位、下一个任务才恢复源条目，中间会画出一帧错位的浮层和空占位；现在浮层落到位的同一帧收起浮层内容，BingDraggable 的 `dragging` 同时变为 false。首页工作流的被拖卡片占位改为同尺寸虚线空槽，拖拽落位不再叠加高亮环；工作台无头与真实库集成场景通过。

0.13.2 修复条目放下后不再显示时 BingDragOverlay 飞向视口左上角：dnd-kit 的归位动画以已卸载或隐藏（0×0）的条目为终点；现在浮层保持拖动时的尺寸，缩小淡出地收进它落下的区域，减少动效设置改为每次松手读取。首页工作流拖到「已完成」或窄屏的其他列投放区时，浮层收进投放区，投放区随后播放「收下」效果；工作台无头场景逐帧断言浮层不离开投放区。

0.13.3 修复 Toast 异步操作的身份判断：同一 action 的原对象和 Vue 代理视为同一个操作，更新文案保持 loading；回调中替换 action，或关闭后重建同 ID 提示，旧 Promise 不再改变新提示。工作台撤销继续使用组件的异步 action，文档正文、API、撤销进度示例与 AI 导出同步到正式版本。

0.14.0 公开代码语言列表、别名规范化、自动主题解析和 token 高亮 API，继续按需加载 Shiki。REQ-31 的正文代码块使用这些包根 API，自行按视口、防抖和输入法状态调度，通过 Decoration 上色；只读正文复用相同行为，版本比较与选区历史仅共用语言头部和原文复制，保留原有差异颜色。看板与文档站精确升级到发布包，正文、API、独立示例及 AI 导出同步；验证与长文测量见 [REQ-31 验证记录](req-31-validation.md)。

0.15.0 为 BingDropDown 增加 `anchor` 虚拟矩形锚点及 `boundary` 局部视口，菜单自动翻转、限制宽高并在 BingScrollbar 内滚动揭示 active 项。REQ-34 用光标矩形和正文 viewport 打开斜杠命令菜单，保留编辑器焦点，不操作组件内部定位 DOM。看板与文档站使用同一精确发布版本；验证覆盖键盘与鼠标、中文组词、普通/Yjs 撤销、图片上传、亮暗窄屏及光标靠近底部时的向上展开。
