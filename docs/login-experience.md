# 登录页交互与视觉

REQ-52 对应 `/login`，按最新需求使用静态猫咪 Logo 和产品场景预览。页面只改变展示和输入反馈，用户名/邮箱登录、保持登录、错误码映射与 `resolveAuthRedirect` 沿用既有契约。注册页保持原布局，登录页的注册链接继续携带 `redirect`。

## 布局与视觉

- 桌面（≥1024px）：最大宽度 1120px，品牌区与表单约为 55:45。品牌区依次为静态 Logo 与产品名、简短介绍“把想法写下来，让进展看得见。”、338px 高的迷你文档卡片、三个可点击的产品亮点。移除原先两行大标题；表单垂直居中。
- 平板（768–1023px）：上方横幅只保留 48px 猫咪 Logo、产品名和一句标语，下方为表单；不显示或加载场景预览。
- 手机（<768px）：静态 Logo 移到卡片标题旁，隐藏品牌长文案和场景，优先展示表单；375×667 下账号、密码、保持登录、注册与登录按钮进入首屏。

沿用 `public/requirement-board-logo.png`，不切换表情或制作大幅插画。全站字体继续使用 Maple Mono NF CN，没有新增字体或图片。亮色表面、正文分别为 `#ffffff`、`#20242a`；暗色为 `#191d22`、`#edf0f5`，实际取值复用 `--bing-*` / `--rb-*`。背景是低对比度网格与柔和渐变。协作者蓝色沿用现有默认值 `#2b6ef3`，另一个演示光标为紫色；暗色下紫色降低亮度。Diff 行沿用正文比较的 `--bing-success-rgb` / `--bing-danger-rgb` 22% 背景，文字保持主题正文色。

## 场景与组件

`app/components/accounts/LoginBrand.vue` 管理品牌内容、亮点选择、媒体查询、轮播时钟和视差；`LoginScenePreview.vue` 只渲染演示卡片。二者只接收登录阶段，不接收账号或密码。预览对读屏软件隐藏，亮点选择与暂停按钮保留清楚的可访问名称和键盘焦点。

预览共用“文档协作体验优化”需求卡片，页头有团队空间、协作者头像和状态，页脚展示同步信息。所有内容都是前端演示，不发起真实编辑、协作或 AI 请求。

| 场景 | 关键画面 | 动效节奏 |
| --- | --- | --- |
| 实时共同编辑 | 小林和阿青两个带姓名标签的光标，依次补充协作方式与修改记录 | 第 500ms、1900ms 开始两段输入；每字间隔 65ms，100ms 淡入，光标以 transform 分步跟随 |
| 版本对比 | 标题旁显示 v2 → v3；旧句红底删除线，新句绿底；下方显示新增/删除数量 | 版本标签 150ms 后出现；删除行 450ms 后以 240ms 淡入上移，新增行 1200ms 后以 300ms 出现，摘要 1900ms 后淡入 |
| AI 协作 | 正文旁有编号标注，气泡提出修改要求，原句更新为具体说明，标注显示“已处理” | 气泡 350ms 后以 300ms 淡入；约 2.0–2.6s 交叉淡出原句和待处理状态，显示修改结果与已处理状态 |

每个场景 4 秒，结束后按顺序循环，并同步选中亮点和说明。鼠标悬停在预览或亮点区域、键盘焦点进入该区域、手动暂停、窗口失焦或页面隐藏时，CSS 动画和轮播计时一起暂停；恢复使用剩余时间，不重播当前场景。手动点击亮点直接展示该场景的完整关键帧，便于在悬停或键盘暂停时阅读；恢复自动播放后，下一场景重新演示过程。

鼠标视差只作用于场景内部的卡片层级：主卡片每轴最多 5px，背景纸张反向 2px，AI 标注卡片相对主卡片最多 1.5px；单个卡片合成位移不超过 8px。指针事件每帧至多更新一次，过渡为 220ms ease-out。没有独立漂浮装饰或循环漂浮动画，静态 Logo 不移动。

## 登录状态联动

| 登录阶段 | 场景反馈 | 表单反馈 |
| --- | --- | --- |
| 输入与待机 | 按上述规则播放，与账号/密码内容无关 | 聚焦标签与边框高亮 |
| 提交中 | 暂停轮播和场景，状态标签显示“同步中…” | 禁用表单与显隐按钮，按钮 loading 和“登录中…” |
| 成功 | 保持场景，状态标签与对勾同步显示“已完成” | 按钮显示对勾和“登录成功”，420ms 后导航 |
| 失败 | 保留失败前的场景画面，状态回到“进行中”；修改输入后恢复播放 | 卡片轻晃 280ms，顶部 Toast 展示错误，输入框标红；修改任一字段即清除 |

场景没有额外成功等待。成功反馈至发起导航使用浏览器同一时钟验证，少于 600ms，不包含后续路由权限检查耗时；减少动态效果时不额外等待。请求或成功反馈期间卸载页面，晚到的响应与计时回调不再导航。

进入工作台时侧栏首帧即为目标宽度，登出时与登录页一起切换到简化布局，均不播放侧栏宽度动画；手动开合仍播放。账号权限和页面缓存边界在导航确认后一起提交，不在等待权限接口期间提前重建旧页面。相关全局契约见 [应用架构](architecture.md#全局界面与主题)。

品牌区和卡片分别以 420ms、延后 100ms 的 440ms 淡入上移，总计 540ms。预览字符预先占位，正文替换使用同一网格单元叠放，场景高度固定；连续动画只改变 transform 和 opacity，不逐帧改宽高或插删字符。标签、状态与注册下划线的反馈为 180ms，错误左右位移为 4px。

## 表单行为

复用 `BingForm`、`BingFormItem`、`BingInput`、`BingButton`、`BingCheckbox` 的公开 API，保持默认 `auto` 校验：首次进入不报错，字段失焦为空或提交后提示必填，有错误的字段在修改时复查。账号 Enter 只聚焦密码；密码 Enter 原生提交，中文组词确认不误提交。

密码显隐使用公开 `suffix` 插槽、`passwordToggle=false` 与 `input` 引用，切换时保留焦点、选区和水平滚动位置。CapsLock 仅在开启且密码控件聚焦时显示在密码输入框下方；不再联动 Logo 或场景表情。

表单按 16px 间隔排列，字段自身的 6px 消息间距计入后，正常状态下控件之间留白为 16–22px。必填校验保留在对应字段下方，空消息最小高度为 0；大写锁定和服务端错误不再预留空白区。桌面卡片内边距 32px，标题至表单 24px，手机标题区 22px。

校验通过后固定本次输入，账号 trim、密码保留原文，忙碌状态拦截重复提交。服务端错误复用全局 `BingToast`，显示在顶部居中位置，使用 `role="alert"`，6 秒后自动关闭，也可手动关闭。每个登录页实例使用独立消息 ID，重试时关闭旧提示，不叠加；修改任一输入清除 Toast、错误描述与字段红色状态，页面卸载只关闭自己的消息。Toast 关闭后错误描述仍通过视觉隐藏文本关联两个输入框，便于继续检查；视觉隐藏文本不再次声明告警，避免重复播报。成功反馈保留在按钮及读屏状态文本中，不占额外布局空间。

错误文案沿用原映射：429 为尝试过多，403 为停用，400/401/422 为账号或密码不正确，其他与断网为暂时无法登录。

## 减少动态效果、加载和清理

系统开启 `prefers-reduced-motion` 时回到第一个场景的完整静态画面，停止自动播放、视差和抖动；仍可手动选择其他亮点，只保留淡入和颜色变化。触屏不启用视差。平板和手机不加载场景模块。

桌面预览在首个动画帧后动态导入，固定尺寸的静态文档占位先呈现；场景模块失败不阻塞表单。离页取消轮播与动画帧、移除媒体查询/指针/焦点/可见性监听，延迟导入返回后不会重新挂载已销毁实例。

已移除 Rive 运行时依赖、WASM、`.riv`、多状态猫咪图片和生成/预览脚本。当前预览使用 HTML/CSS 与已有图标组件，没有新增图片、SVG 文件、字体或其他独立静态素材，新增静态素材为 0 字节。场景组件的 JavaScript/CSS 仍有代码体积；这不等于总页面资源为零，也不是生产环境网络性能测量。

## 验证与交付视图

```powershell
$env:BROWSER_TEST_SCENARIO='login'
pnpm test:browser:workspace
pnpm test:auth
pnpm typecheck
```

无头专项 `tests/browser/login-experience.mjs` 使用真实页面、组件和主题，覆盖三场景实际 CSS 时间轴、逐字输入、暂停续播、手动选择、四秒轮播、登录状态同步、静态 Logo 与无 Rive 资源请求。验证全部表单交互与认证分支、Toast 关闭/连续重试/修改清除、错误出现时卡片与按钮位置稳定、成功等待、卸载后不导航、减少动态效果、触屏以及装饰模块加载失败/延迟返回。

布局覆盖 320、375、768、960、1024、1440px 的亮暗主题，检查控件之间的紧凑间距，以及表单与预览正文的实际颜色对比度不低于 4.5:1。设置 `BROWSER_TEST_ARTIFACT_DIR` 导出 375/960/1440px 各亮暗一份截图，三个场景各亮暗一份关键帧，以及登录中、错误 Toast 和成功的状态画面；截图在进场和主题过渡结束后采集，不提交 Git。

夹具拦截认证响应，不连接业务数据库，不能代替真实密码验证、会话持久化、系统输入法实机或生产网络首屏性能基准。此任务没有修改认证 API 或会话逻辑，不运行无关数据库/构建检查；既有账号组件回归仍可用 `BROWSER_TEST_SCENARIO=consumer-accounts`。
