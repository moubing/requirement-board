# 子任务与需求状态汇总设计

状态：**尚未实现**。本文件保留后续子任务设计；账号注册、审批、邀请和角色管理已由 [accounts.md](accounts.md) 说明，共同编辑见 [collaboration.md](collaboration.md)。

现有文档按 [文档类型与模板](document-types-and-templates.md) 流转，四类文档均支持多人负责，职业角色不限制正文编辑或现有属性动作。下述设计不能直接作为当前 API 的权限规则。

## 范围与待决事项

继续使用固定项目、内置角色和现有审计表。需求拆成子任务，由执行人维护，父需求状态按阶段汇总。首版建议阶段内并行、阶段间顺序执行；暂不支持任意依赖图或通用权限编辑器。

实施前需确认：

- 子任务先覆盖需求，还是同时覆盖缺陷等类型。
- 设计、开发、测试、验收、发布哪些阶段必需，哪些允许明确跳过。
- 现有 `requirement_assignees` 多人关系及接口 `assigneeIds` 如何与规划权限配合；当前没有主负责人概念。
- 从当前人工状态流转切换到汇总状态的时机，以及存量文档如何确认计划。

## 动作权限建议

| 动作 | 授权 |
| --- | --- |
| 查看、创建和编辑正文、保存版本 | 启用的项目成员，沿用现有规则 |
| 规划阶段、拆分、指派、转交、取消和重新打开任务 | 超级管理员、项目管理员、产品 |
| 开始或完成任务 | 具备对应角色且被指派的成员 |
| 测试或验收退回 | 被指派的执行人，在允许退回的状态操作 |
| 代操作或强制处理 | 超级管理员，通过管理入口填写原因 |

任务类型对应 `designer/developer/qa/product/ops`。多角色按并集合并，但仍须满足本人负责、当前状态和前置条件；项目管理员资格仍只能由超级管理员管理。

服务端依次检查账号启用、项目范围、动作权限、任务指派、状态和工作流版本。未知动作拒绝；角色撤销或任务转交后，旧页面不能继续执行。管理员代操作保留实际操作者，不冒充执行人。

## 子任务与阶段

子任务有待处理、处理中、已完成、已取消四种状态。未指派任务不能开始；负责人必须是同项目启用成员且具有所需角色。受阻另记原因，不算完成，也不解除后续阶段条件。停用负责人或移除其角色时，保留进度并提示转交。

计划确认后，按阶段顺序找到第一个未通过阶段：

| 情况 | 汇总结果 |
| --- | --- |
| 计划未确认 | 待整理 |
| 启用阶段没有有效必做任务 | 待安排，提示补齐任务 |
| 本轮尚无任务开始 | 待设计、待开发、待测试、待验收或待发布 |
| 本轮已有任务开始或完成，但未全部完成 | 对应阶段进行中 |
| 本阶段全部必做任务完成 | 检查下一阶段 |
| 全部启用阶段通过，且至少完成一项实际工作 | 已完成 |

首版所有未取消任务都为必做项。取消全部任务、空阶段或全部跳过不能自动完成需求；明确跳过阶段需记录操作者和原因。

测试或验收退回时，重开被指出的前置任务及受影响的后续验证任务，保留历史结论。新轮次尚未开始修复时显示待修复，不能沿用上一轮完成记录认定本轮已开始；未受影响的开发任务可保持完成。

## 数据与一致性

| 对象 | 拟增加的内容 |
| --- | --- |
| `requirements` | 计划确认信息、工作流版本和生命周期；保留完整负责人名单 |
| `requirement_stages` | 需求、阶段代码与顺序、启用/跳过决定、本轮信息；同需求阶段唯一 |
| `requirement_tasks` | 阶段、类型、标题、执行人、状态、受阻原因、轮次与时间 |
| `audit_events` | 规划、指派、开始、完成、退回及父需求状态变化，关联触发操作 |
| `requirement_statuses` | 汇总状态的稳定代码；名称与颜色只用于显示 |

阶段、任务和负责人均受项目边界约束。任务动作在同一事务内锁定所属需求，检查预期工作流版本，更新任务、重算状态并写审计；重复请求不能重复执行或记账。

父需求状态可持久化供列表查询，但启用汇总后须由流程事实产生。届时须同步收紧网页与 Agent 的创建/PATCH 入口；管理员强制处理也必须更新流程事实，不能单独写一个下次汇总就会消失的状态。

正文和工作流继续独立。测试、验收记录可关联当时的 revision；之后修改正文只提示结论未覆盖的新内容，是否重开由授权人决定，不因每次文字修改自动退回。

2. 旧文档保留原状态并标为待确认计划；由授权人核对后启用汇总，不编造历史任务或时间。
3. 增加服务端动作服务与可用动作 DTO，再接入按阶段展示、本人任务及待转交提示。
4. 验证角色与指派越权、空阶段、部分完成、退回轮次、重复请求、并发完成和审计回滚。
5. 运行流程纯逻辑、API 和相关无头浏览器测试，更新现行架构与类型文档。
