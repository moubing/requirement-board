# REQ-10 长文档优化验证

测量日期：2026-10-19。对照为 `main` 的 `c36ddd3` 与 npm `@moubing/bing-ui@0.11.0`；候选为 `moubing/feat-REQ-10` 和组件库 0.11.1 构建产物。以下数据来自真实 Nuxt 路由、本机 PostgreSQL、WebSocket 协作与原图上传服务，不使用 API 或路由桩。

首轮三轮全文滚动的样式重算均值从 **224.2 降至 41.5 ms/s（约减少 81%）**；本报告定义的渲染 CPU 时间均值从 **449.9 降至 135.5 ms/s（约减少 70%）**。比较热切换 P95 从 **414.8 降至 265.2 ms**。首轮返回详情 P95 为 **501.3–546.5 ms**。后续针对返回流程补充分段计时并优化；同样本重跑的基线为 **486.4–500.3 ms**，优化后为 **302.9–319.0 ms**，详见下方“返回详情的第二轮优化”。这些是本机无头浏览器结果，不能据此宣称所有真实网络与设备的验收目标已达成。

## 改动与边界

- 图片保留稳定的媒体、题注及缩放容器；工具条和缩放手柄按悬停、选中、聚焦及拖动状态创建，宽度观察器随交互启停。保留预览、复制、对齐、删除、键盘缩放和中文题注输入。
- BingCursor 全部停用时提前退出；编辑区自动模式使用稳定根标记和局部悬停样式，编辑及只读状态均不写正文节点。行内 cursor、固定状态、按压与指针捕获沿兼容路径处理。
- 比较器首次打开才创建，后续复用 DOM；隐藏期间暂停计算与几何监听。每个实例最多缓存两组结果及视图状态，版本正文最多保留六份，按账号、文档、代次和不可变正文身份失效。
- 仅缓存最近两篇详情。离页仍执行可靠备份；停用断开协作连接、清空感知状态并暂停视觉工作，保留原 Y.Doc。返回先核对权限、元信息、锁与代次，再合并远端增量。淘汰或账号变化时销毁实例。
- 没有引入全文虚拟化、Worker、正文格式或 API 契约变更；目录索引等 P2 工作暂未扩大。

## 返回详情的第二轮优化

2026-10-19 00:44–00:54（Asia/Shanghai）重新测量。先在首轮交付代码上只增加 User Timing 得到 `return-before`，再使用相同计时和样本运行 `return-after`。两组均使用 npm `@moubing/bing-ui@0.11.1`、相同浏览器 148.0.7778.96、视口与默认动效；关闭 Playwright 调试日志，测量期间不并行构建或执行其他测试。正文哈希、37 张原图及 5,288,560 字节总量与前文一致。新基线和首轮数值存在运行波动，收益只按本轮前后数据计算。

### 实现

- `setEditable(value, false)` 仅改变编辑状态，去掉无正文变化时的全文导出和 v-model 回传。输入、远端正文变化和撤销/重做仍正常更新。
- 路由仍等待账号权限检查。缓存页激活后并行读取详情与本轮协作状态；预取期间不合并、不连接、不开放编辑。详情校验通过后才消费未取消的协作响应，继续核对锁和 editEpoch、合并原 Y.Doc，然后恢复编辑。
- 版本列表、关联信息改为后台刷新，保留加载、错误和重试反馈；失败不阻塞已通过必要检查的正文。离页取消该轮请求，预取不跨次复用。
- `window.__RB_DETAIL_RETURN_TIMING__` 仅在性能场景开启，不默认采集或上报。User Timing 按 run 记录各阶段，浏览器脚本保存阶段起点、耗时和事件数；分析脚本输出对应分位数。

### 分段结果

下面汇总 80 次返回，以路由账号检查开始为零点。起点与耗时均为中位数，各行不是同一条样本，且存在并行、嵌套，不能相加。请求阶段包括客户端排队、响应解析等，不是纯网络或服务端时间。

| 阶段 | 优化前起点 / 耗时 ms | 优化后起点 / 耗时 ms |
| --- | --- | --- |
| 账号权限请求 | 0.0 / 6.2 | 0.0 / 6.2 |
| 详情请求 | 19.4 / 141.2 | 19.6 / 141.5 |

协作请求提前约 201 ms 发起，其 Promise 耗时与页面激活、详情和布局重叠，因此数值变大不能解释为网络变慢。实际进入协作合并由约 270 ms 提前到 195 ms。辅助信息已移出编辑恢复的关键路径，阅读位置恢复也提前开始；它们的等待区间同样与其他工作重叠。仍需单独的网络/服务端及 CPU 采样才能继续细分这些区间。

浏览器内部 `editable` 累计中位 / P95 从 **317.8 / 385.2 ms** 降至 **220.7 / 238.0 ms**；`frames-ready` 从 **383.3 / 433.1 ms** 降至 **275.9 / 295.4 ms**。这两项不包含外部自动化观察等待。80 次返回的 `document-export` 事件由 **80 次降为 0 次**，各轮都保留一次账号、详情与协作读取/合并记录。

详情请求在浏览器侧仍约 141 ms，协作合并约 15 ms，恢复后的布局、阅读位置与帧等待仍有成本；本轮没有把它们解释为不可优化的下限，也没有修改接口或持久化格式。
