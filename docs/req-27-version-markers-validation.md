- 工作区 `version-markers` 无头场景覆盖三类标记及连续删除、悬停/卡片、循环定位、恢复/撤销、标注取消/确认、上传门禁、AI 锁/只读、比较定位、Cookie 刷新、正文宽度和 JSON 不变、标注编号避让、字号/行高/宽度重测、滚出视口关闭、页面隐藏与恢复、保存新版本后清空及无基线隐藏。
- 同一场景检查亮暗主题的 320/390/960/1440px，ContextMenu、Shift+F10、Escape/外部点击后的选区与焦点恢复，以及 390px 触屏的24px热区；正常动效和减少动态效果均有覆盖。

- 编辑器 `version-markers` 场景使用两个真实 Tiptap/Yjs 页面，覆盖远端输入、单块恢复、个人撤销及 AI 正文应用后的同步标记。两个页面由测试驱动传递 Yjs 状态，不连接业务数据库或真实 WebSocket。
- 既有 `annotations` 场景通过，覆盖多行/窄屏避让、标注定位、输入锁、原文编辑确认、完成回执等交互。
- 既有 `detail` 场景通过，覆盖工作区属性、段落样式、面板宽度/断点、阅读锚点和比较布局。

全量单测第一次使用默认5秒超时，有 Agent 子进程测试超时及连带失败；单独复跑后，以4个 worker、30秒单测上限完成全量验证。未修改项目测试配置或业务实现来放宽断言。

编辑器夹具运行时出现 `ofetch` 依赖预扫描警告，随后 Vite 完成依赖优化；两个页面没有 `pageerror`，协作场景通过。工作区夹具已有显式依赖别名，未出现同一警告。本次没有扩展修改测试工具链。

## 页边标记视觉复核

根据实际使用反馈，修改竖线调整为与版本比较一致的 `--bing-warning-strong` 琥珀黄色，删除三角改为8×3px圆角短横线。短横线和竖线共用中心轴，热区保留12px/触屏24px。

复核发现 Tooltip 的行内基线使8px高的删除锚点下移约7px；已通过业务锚点的 flex 布局及按钮绝对定位消除偏移。无头测试新增对实际绘制符号的测量：四种宽度、亮暗主题下，三类符号的中心轴以及删除符号与段落间隙中心的误差均小于1px。版本标记完整交互场景和类型检查通过。

## 长正文开关对照

使用现有本地只读导出的 REQ-8 v7 样本及对应原图：197 个顶层块、37 张图片、16 张表格。Windows、Node 24.18.1、无头 Chromium 148.0.7778.96，1440×1000，正常动效，无 CPU 降速。测量期间不并行运行构建或其他测试。

`tests/browser/version-markers-performance.mjs` 在开关两种状态各运行三轮，顺序交替。每轮等待字体与原图解码，预热一次输入后，输入78个字符（55ms间隔），然后滚动至文末并反向。每轮断言正文仍有197个顶层块、37张原图加载成功、滚动覆盖九成以上；实际六轮正文高度均为84,312px、最大 scrollTop 均为83,501px。

此次对照未显示开启标记带来明显的输入或滚动退化。正文核对按约6ms预算分片，普通输入事务不遍历全文或测量标记；标记、修改状态及进入最新版本比较时共用 Diff 结果。单个超大块仍可能超出一次分片预算，需要另选极端样本评估。

事件间隔没有包含所有编辑器后续微任务；两个 rAF 也是浏览器内部代理值，均不能称为用户实际看到的最终呈现延迟。本次使用 Vite 工作区夹具，不代表生产网络、低性能实机、真实 Windows 中文输入法或所有浏览器。卡片、一般排版变化和双页同步由功能回归覆盖，未把它们混入这组性能数据。

初次试跑发现预热后的撤销可能与夹具装载合并，导致部分轮次撤掉整篇长文；该组数据已作废。正式记录为修正预热流程、增加每轮完整性和滚动断言后，于2026-11-08 19:49（北京时间）完成的六轮结果。原始样本与图片未修改；临时浏览器、缓存、截图和本次原始测量文件在验收后清理。

## 复现

按 [开发文档](development.md#按改动选择验证) 设置 `BROWSER_TEST_SCENARIO`。功能场景用 `version-markers`，开关对照用 `version-markers-performance`；后者另需 `BROWSER_TEST_DOCUMENT_V5`、`BROWSER_TEST_IMAGES_DIR` 和 `BROWSER_TEST_ARTIFACT_DIR`。浏览器默认无头，所有路径通过当前运行的环境变量传入，不提交机器专属配置或业务正文。
