# 首页工作台

首页回答“我现在该做什么、项目里发生了什么、团队手上有多少事”。REQ-26 起采用岛屿布局：灰色底上四块圆角面板，第一屏是「我的工作」（三列工作流，标题旁是等你验证与停滞两个数字）和「项目动态」，往下是「负载」与「完成节奏」。状态流程见 [文档类型与模板](document-types-and-templates.md)，列表筛选契约见 [文档查询](requirement-queries.md)。

## 范围

- 工作流只包含需求、缺陷、待办的待处理 `queued`、进行中 `doing`、测试中 `testing` 三列；说明的状态与这三列不对应，不进入工作流、关键数字和团队负载。
- 「我的」卡片是我负责（负责人之一）的文档；另外，我提出且处于测试中的文档以「等你验证」出现在测试中列，不论负责人是谁。
- 卡片在列内按最近有效活动升序排列，最久没进展的在前。卡片超过 `FLOW_CARD_LIMIT=300` 时只返回最该处理的部分，`truncated=true`；数字仍是全部。

## 停滞

最近有效活动 = 创建、正文编辑（`requirement_edit_events`）、保存正式版本、状态变化（迁移日志除外）中最晚的时间。仅修改标题、负责人或优先级不重置计时；编辑收据的 `block_ids` 须含正文节点，仅有 `$title` 或为空的收据不计入，同时修改标题与正文仍计入。SQL 定义在 `server/services/document-activity.ts`，首页卡片、关键数字与列表 `stale=1` 共用，时钟取查询事务时间。

阈值集中在 `shared/workbench/home.ts` 的 `STALE_DAYS`：待处理 14 天、进行中 3 天、测试中 3 天。超过阈值为提醒，超过两倍为警示；卡片显示“N 天没有进展”。

## 数字与列表一致

首页每个数字都链接到带相同筛选的文档列表，数量由同一 SQL 条件计算：

| 数字 | 列表筛选 |
| --- | --- |
| 列头数量 | `assignee=me&statusId=<该列状态>` |
| 等你验证 N | `reporter=me&statusId=<测试中>` |
| 停滞 N | `assignee=me&stale=1` |
| 负载格子 | `assignee=<成员ID或unassigned>&statusId=<状态>` |

链接由 `app/utils/requirement-list-link.ts` 生成字符串 URL。列表页只要 URL 含 `q`、`documentType`、`statusId`、`assignee`、`reporter`、`stale` 任一参数，就以 URL 为准替换会话中保存的全部筛选；提出人和停滞没有对应下拉框，以可移除的标签显示。

## 拖拽与菜单

卡片可在三列之间拖动，拖到底部停靠区可改为已完成（窄屏下停靠区同时提供其他列）。拖拽使用 bing-ui `BingDragDrop`：鼠标移动超过阈值开始，触屏长按 300ms 开始，普通点击仍打开文档，Esc 取消。每张卡片的「更多操作」菜单提供同样的「改为 X」选项，键盘用户通过菜单完成。整卡链接与菜单放在同一张卡片内部，菜单在链接上层；悬停位移或等待透明度变化时，点击菜单也不能命中整卡链接。菜单使用 `bottom-end`，优先在按钮下方右对齐；组件库 0.18.3 修复原生锚点宽高丢失。回归同时覆盖普通动效和减少动效下的真实点击、常驻可见性与菜单横纵坐标。

工作流列与窄屏投放区可能同时挂载，即使列被 CSS 隐藏也仍已注册；投放区使用独立的 `dock:<状态代码>` 区域 ID，放下后再映射为业务状态，避免投放区卸载时破坏原列的后续拖放。

拖动中「我的工作」用主题色描边和浅光环强调，动态、负载与完成节奏降低至 30% 不透明度。底部「已完成」初始为 440×88px，拖入后向上和两侧扩大到 560×132px，实际命中范围同步扩大，标题位于上沿以避开拖动浮层。窄屏投放区总宽受窗口约束，三个目标只向上增高、不挤动彼此；减少动效时直接切换尺寸。强调和投放区均不改变四块面板的布局，取消或收尾结束后恢复；投放后的约 760ms 内保持展开。

拖动中可放下的列描虚线、指针所在的列染色描实线，不再显示「松手改为…」文字。工作台关闭 BingDragDrop 的边缘自动滚动（`:auto-scroll="false"`）：落点只看列或投放区，不涉及列内排序，宽屏列内各自滚动，窄屏的投放区已包含其他列；而投放区固定在窗口底部，开着自动滚动会让指针移向投放区时整页下滚。浮层落位的那一帧由 bing-ui 把位置交还给卡片（0.13.1 起），被拖卡片留下的虚线空槽与浮层同时消失；拖动落位的卡片不再叠加高亮环，菜单移动与撤销仍然高亮。落到底部投放区时卡片会离开当前视图（已完成，或窄屏下未显示的列）：浮层缩小淡出地收进投放区中心（bing-ui 0.13.2 起），投放区多停留约 760ms 播放「收下」效果（染满状态色、轻沉回弹、标记变为实心圆章、一道光扫过、外圈荡开），其余投放区变淡，随后整条退场；减少动效时只保留配色变化。

提交走 `PATCH /api/requirements/:id`，携带 `statusId` 与 `expectedStatusId`（拖动时看到的状态）。卡片先乐观移动，等待期间不可再次拖动：

- 成功：Toast「已将 KEY 改为X」，带「撤销」按钮（至少 6 秒）。撤销同样携带 `expectedStatusId`，成功提示「已撤销，KEY 恢复为X」。
- 409 `STATUS_CONFLICT`：别人已改过状态，卡片回到服务端最新状态，提示原因，不覆盖。
- 423：Agent 编辑锁生效，卡片退回并提示「稍后再试」。
- 其他失败：卡片退回原列并给出原因。

逻辑在 `app/composables/use-workbench-flow.ts`；成功后失效相关列表、负载和完成节奏查询。

## 项目动态

`GET /api/workbench/activity?kind=all|status|assignee|create|revision&cursor=&limit=30` 返回全项目事件：属性日志中的状态、负责人、优先级变化（迁移来源除外），文档创建，以及 v2 起的正式版本。按时间倒序、游标分页（`limit` 1–50），未知参数返回 400。操作人及指派对象统一显示成员姓名，当前用户也不替换为「你」。`mine` 表示我负责、我提出或这次指派给了我，界面在条目左侧加细主题色线。

界面按今天/昨天/更早分组，筛选保存在会话中；距离底部不足一个列表可视高度时预加载下一页，预加载距离至少 240px，随当前滚动视口高度计算。进入范围即请求，无需触底；加载中、已到末页或上次失败时不自动重复请求。切换筛选、刷新和分页都保留原列表，加载反馈按请求类型区分：

- 首次读取、切换筛选和刷新：持续等待超过 150ms 才显示半透明遮罩，淡入淡出各 100ms。遮罩仅覆盖列表，标签可继续切换，旧条目在等待期间不可交互；响应到达即更新数据并恢复操作，不等待动画或强制停留，淡出期间不拦截点击。
- 进入底部预加载范围或点击「加载更早的动态」：持续等待超过 150ms 后，仅在列表底部显示转圈图标和「正在加载更早的动态…」。不显示遮罩、不暂停滚动，已有条目仍可阅读和打开；同一页请求期间重复进入范围或触底不重复发送，成功后追加条目。底部保留 40px 的反馈区域，避免加载提示出现时挤动内容。

同类连续请求沿用等待状态，分页中改选标签时重新计算遮罩的延迟，请求完成或组件卸载取消计时；减少动效时保留延迟判断，遮罩直接显隐、底部图标静止。筛选成功后回到顶部，同筛选刷新保留阅读位置；晚到的旧请求不能覆盖新筛选或追加旧页。账号/项目变化时立即清空旧数据。

加载失败保留已有内容并可重试。重试沿用失败请求的模式：刷新失败从首页重读，加载更早失败则重试原游标，不根据已有条数推断。

## 团队负载

`GET /api/workbench/team-load` 按成员 × 三个状态给出数量，未禁用的项目成员都列出，当前用户在前，其余按总数降序；最后一行为「未指派」。负责人通过 `requirement_assignees` 计数，多人负责的文档在每位负责人下各计一次，所以合计可能大于文档数。格子按数量分 0–4 级着色，悬停或聚焦时同行同列保持高亮、其余变淡，点击打开对应列表；数量写在格子里，不另设说明行。当前用户用头像外圈标记。

悬停描边使用一个不拦截事件的独立指示框，以 160ms 在格子间平滑移动并跟随状态颜色。经过行列间隙时保留指示框和同行同列强调，离开表格后淡出；键盘焦点仍在表格内时保留焦点提示。键盘聚焦立即定位，点击与触屏轻点立即打开列表，触屏不留下模拟悬停。格子间距 8px，指示框保留 2px 间隔和 2px 边线，滚动容器四周留 6px；框不占布局空间，正常行位于固定表头/底部行之下，选中未指派格子时显示在其上方。减少动效时直接切换。

表格内容高度固定为 300px（触控环境 316px），超出时在 `BingScrollbar` 内滚动。表头固定顶部，未指派行固定底部；三者共用同一滚动视口和列宽，窄屏横向滚动仍然对齐。指示框按实际格子位置测量，滚动、窗口尺寸或数据变化后即时校准，避免追赶滚动的拖尾；卸载时清理尺寸观察和待执行测量。键盘聚焦格子时，为表头和底部行预留滚动边距。

## 完成节奏

`GET /api/workbench/completions?scope=team|mine` 返回近 12 周（周一对齐，Asia/Shanghai）每天进入已完成的文档：

- 每篇只计最后一次进入已完成，且当前仍为已完成；重新打开后再完成只算最后一次，已关闭不算。
- `mine` 按完成那一刻的负责人统计：取完成前最后一次负责人变更的结果，没有则取之后第一次变更的原值，再没有则用当前负责人。
- 迁移日志不计入；`dataStart` 是项目第一条属性日志的日期，之前的日期格子用斜纹表示无记录，不推测历史。统计口径只写在本文档，界面不放说明文字。

日历为纯组件（无图表库），每个格子是按钮。悬停描边是日历内独立的指示框，不拦截鼠标事件；进入格子后用 160ms 移动到目标位置，在同一格停留 160ms 才更新右侧详情。快速掠过或离开格子会取消待生效的预览，经过间隙时保留当前详情及指示框目标，避免来回跳动；移入详情后指示框回到正在预览的日期。日历滚动、范围或日期窗口变化、组件卸载时清理待生效预览。

点击或触屏轻点立即固定日期，再次点击或 Escape 取消固定；键盘聚焦立即预览，不等待悬停计时。减少动效时指示框直接移动，仍保留停留判断。日历、间隙和详情属于同一预览区域：移入详情或滚动详情时保留最近预览日期；鼠标与键盘焦点都离开组合区域后回到固定日期，未固定时展示最近有完成记录的日期。鼠标点击留下的焦点不阻止离开后恢复。

详情固定日期标题和完成数，列表单独使用 `BingScrollbar`。日期或已返回数据的范围（团队/我的）变化时回到顶部，标题与内容以 160ms 从半透明、下方 4px 处淡入归位，面板背景和尺寸保持稳定。内容立即更新，不等待退场、不短暂清空；连续切换取消上一段动画并保留同一内容容器，卸载时清理动画。减少动效时直接更新，同日同范围刷新不重播动画并保留阅读位置。无记录、零条、多条、更新中和失败状态均保持区块高度；更新期间保留已有内容。

## 接口与刷新

四个接口都使用 `requireAppContext`，只读 REPEATABLE READ 事务，响应 `Cache-Control: no-store`，拒绝未知参数，不接受调用方指定项目或用户：

| 路径 | 内容 |
| --- | --- |
| `GET /api/workbench/flow` | `me`、`statuses`（五个状态代码到 ID）、`cards`、`counts`（三列 + verify + stale）、`truncated`、`asOf` |
| `GET /api/workbench/activity` | `items`、`nextCursor`、`asOf` |
| `GET /api/workbench/team-load` | `statuses`、`rows`、`asOf` |
| `GET /api/workbench/completions` | `scope`、`today`、`startDate`、`dataStart`、`items`、`asOf` |

页面在 SSR 预取并在客户端挂载时读取；四个区块各自显示加载、失败与重试，一块失败不影响其他区块。没有轮询，查询失效与窗口重新聚焦时刷新。

## 布局

页面底色为 `--ui-navigation`，面板为实色白底（暗色为深灰）、12px 圆角和浅边线，面板间距 12px（≤760px 为 8px），面板内不再嵌套装饰面板。工作流列使用中性浅底，列头为状态圆点、名称和数量徽标；拖动落点才使用整列状态色。卡片 8px 圆角和浅边框，以标题为主，顶部集中类型、编号、优先级、负责人和提醒，三个点菜单按钮常驻显示，触控环境保持 44px 命中区。

卡片信息按自身宽度适配：仅当前成员负责时隐藏重复头像，多人或他人负责时保留头像/人数；先隐藏普通更新时间，保留停滞和等你验证。特别窄的桌面卡片将提醒换到第二行。完整负责人通过无障碍描述保留，菜单按钮可通过 Tab 到达。拖动浮层使用相同的宽度适配。

- ≥1101px：桌面首行根据窗口可用空间稳定定高，首选 554px（列表 440px 加标题、列头及内边距），最小 380px。桌面网格先预留下排的实际高度（含日历上下排布），首行在剩余空间内收缩，避免整页只溢出几像素。卡片数量、标题换行与空列不改变首行高度；5→6→5 张只改变列内滚动，下方两块面板位置保持不变。空间不足以容纳最小首行与下排时，正常滚动整页，不压缩下排固定内容或截断页面。三列等高、空列保留投放区；项目动态跟随首行高度，不能用自己的内容撑高首行。下方「负载」与「完成节奏」并排。
- ≤1100px，或导航展开后工作区可用宽度 ≤1000px：四块面板单列排布，每列显示前 5 条并提供「查看全部 N 条」，动态限高 420px，避免临界桌面宽度把卡片挤成窄条。
- ≤760px：工作流用 `BingTabs` 切换单列，停靠区包含其他列与已完成。

负载与完成节奏横向排布时内容区同为 300px（触控 316px）。完成节奏根据自身容器宽度适配，≤620px 时日历与详情上下排列，详情独立高 176px；此时仅完成节奏增加高度，负载不被拉伸。加载占位和错误状态遵守相同高度规则。

响应式全部由 CSS 实现，SSR 与客户端输出一致。状态颜色：待处理 `#2f6fed`、进行中 `#c15d2b`、测试中 `#0891b2`、已完成 `#198754`、已关闭 `#667085`。

工作流列、项目动态、完成详情及页面滚动使用 `BingScrollbar`；负载表格和完成日历显式启用横向滚动，窄屏下保持内容可访问。工作流的列标题保持固定，滚动与拖拽沿用组件公开能力，列表内保留卡片聚焦描边所需留白。
